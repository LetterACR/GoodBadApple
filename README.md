# Bad Apple — 终端字符画播放器

把本地视频逐帧转成字符画，在终端里按原始帧率播放，同时用 pygame 同步播放背景音乐。

支持两种渲染方式：经典的 **ASCII 密度字符**，以及 **Braille 点阵**（2×4 点/字符，黑白下的极限分辨率）。

项目名来自最经典的素材 Bad Apple!!，`data/` 里收的也基本都是网络名场面（Rickroll、甩葱歌、千本桜、Girls Band Cry OP 等）。

最新版本更新：2026.10.2

## 简介

本项目基于 [CallMeToProgram/Bad-Apple](https://github.com/CallMeToProgram/Bad-Apple) 的原始实现，并参考了 [CalvinLoke/bad-apple](https://github.com/CalvinLoke/bad-apple) 的性能优化思路，做了一系列工程化改进，并新增了 Braille 点阵渲染。

核心流程：

1. 用 OpenCV 逐帧读取视频，把每帧灰度值映射到字符表（ASCII 密度字符或 Braille 点阵）；
2. 在终端用 `curses` 逐帧刷新显示，`FpsTimer` 对齐时间轴；
3. 用 `pygame.mixer` 同步播放背景音乐；
4. 转换结果按「分辨率 + 明暗 + 字符集」缓存到本地，下次播放直接读取，无需重复转换。

本项目改编内容大部分使用 AI 编写。

## 特性

- **向量化转换**：基于 numpy 的整帧映射，不是逐像素循环，1080p 视频转 180×60 也就几十秒。
- **Braille 点阵模式**：一个字符塞进 2×4 个点，90×30 窗口能出 180×120 = 21600 个点，是 ASCII 的 8 倍；配合 Bayer / Floyd 抖动在黑白终端下换回灰阶。
- **明暗自适应**：启动时用 OSC 11 转义序列（`COLORFGBG` 兜底）探测终端背景色，自动决定是否反转字符映射；深色和浅色终端的缓存分开存放，换终端不用重新转换。
- **多级缓存**：分辨率 + 明暗 + 字符集全部编码进缓存文件名，重复播放直接读缓存；新设置若恰好命中已有缓存（抽帧/插值也一致）也会自动复用。
- **明暗取反复用**：只有**反明暗**的同名缓存时，直接把那份取反来用（166 MB / 5306 帧的缓存约 1.9 秒），不重新解码视频；结果和重新渲染完全一致。缓存菜单里有一键「⇄ 用深色缓存取反生成浅色版」。
- **尺寸自适应**：默认分辨率按原片比例算（`行数 = 列数 × 原片高 ÷ 原片宽 ÷ 2`），装不下时再等比缩小，不会拉成"宽版普京"。
- **帧率补偿**：`FpsTimer` 用绝对时间轴累加而非 `time.sleep(1/fps)`，长视频不会累积漂移导致画面和音乐跑偏。
- **终端安全**：注册 `SIGINT`/`SIGTERM` 与 `atexit` 钩子，Ctrl+C 或中途崩溃后终端不会残留在 curses 状态。
- **缩放自适应**：播放中改变窗口大小会按新尺寸重排画面，不用退出重来。
- **方向键菜单**：作品 / 视频 / 音频 / 缓存 / 字符集全部走同一套方向键菜单，非 TTY 自动回退编号输入；每一层都能 `Esc` 原路退回（设置屏 ⇄ 缓存菜单也能来回）。
- **一屏设置**：分辨率、字符集、帧率等摆在一屏，默认高亮「开始转换」，一路回车即可开跑。

## 环境要求

- Python 3.9+（本项目在 3.11.3 上验证）
- 支持 ANSI 转义的终端，且必须在 TTY 下运行（播放依赖 `curses`）

## 安装

在 `Bad-Apple/` 目录里安装依赖：

```bash
cd Bad-Apple
pip install -r requirements.txt
```

依赖：`numpy`、`opencv-python-headless`、`pygame`，Windows 上额外需要 `windows-curses`（标准库没有 curses）。

## 快速开始

1. 把视频放进 `data/<作品名>/`，音频放同一目录（文件名相同会自动配对）：

   ```
   data/
   └── rickroll/
       ├── Rickroll.flv
       └── Never Gonna Give You Up.mp3
   ```

2. 在 `Bad-Apple/` 目录里运行：

   ```bash
   cd Bad-Apple
   python3 "Bad Apple.py"
   ```

3. 按方向键选作品、选缓存即可。若该视频已有缓存，直接挑一个就开始播：

   ```
     ▸ 180x60  braille [floyd|g1.5]   25 fps   ← 上次使用
       180x60  braille [bayer|g1]     25 fps
       180x60  block                  25 fps
       180x60  simple                 25 fps
       180x60  classic                25 fps
       ⋯ 重新设置

     ↑↓ 选择   Enter 确认   Esc = 重新设置
   ```

   选「重新设置」进入设置屏；首次转换会自动进入。播放中按 `q` 或 `Esc` 退出。

   > 底部提示会把 `Esc` 的落点直接写出来（`Esc = 重新设置` / `Esc = 不使用音频（静音播放）`），不写笼统的"取消"——不同屏的 `Esc` 落点不同，见下文按键表。

也可以跳过扫描直接指定文件：

```bash
python3 "Bad Apple.py" -v data/rickroll/Rickroll.flv -b "data/rickroll/Never Gonna Give You Up.mp3"
```

## 界面操作

所有选择都走同一套菜单，只有真正需要时才弹：

| 场景 | 出现时机 |
| --- | --- |
| 选择作品 | `data/` 下有多个作品时 |
| 选择视频 / 音频 | 同一作品里有多个时；只有一个则自动采用 |
| 选择缓存 | 该视频有任意缓存时（当前背景没有的话，菜单里给出「取反生成」和「切换终端背景」两项） |
| 设置屏 | 没有可用缓存、选了「重新设置」，或加了 `--setup` / `--rebuild` |
| 字符集 / Braille 抖动 | 设置屏里点「字符集」，或首次转换时 |

这几屏**可以逐层退回**：选视频 → 选作品、选音频 → 它上一屏、设置屏 ⇄ 选缓存，
按 `Esc` 即可（逐屏落点见下文按键表）。作品菜单是第一屏，没有上一层。

「选择缓存」和「设置」两个菜单的标题会带上当前的终端背景判断，例如 `选择缓存 · 深色终端`，方便一眼确认明暗对不对。

「选择缓存」菜单**永远**带一个 `⇄ 切换为深色/浅色终端` 项。当前背景一条缓存都没有时（例如只有浅色缓存），菜单里会多出一项把它用起来：

```
选择缓存  ·  浅色终端  ·  无浅色终端缓存
  [1] ⇄ 用深色缓存取反生成浅色版   把 2 个深色缓存翻过来，秒级，不重新解码视频
  [2] ⇄ 切换为深色终端             切换到深色终端后可用 2 个缓存
  [0] 重新设置
```

`[1]` 是"我的终端确实是浅色，帮我生成浅色缓存"，无损且几秒完成（见下文"缓存说明"）；`[2]` 是"其实我的终端是深色，刚才判断错了"。两者别混：切错了会看到负片。

完整的界面状态图和常见流程见 [UI.md](Bad-Apple/UI.md)。

> **探测时机**：终端背景在**任何菜单出现之前**就用 OSC 11 查询好了。这不是随意选的——菜单会切到 curses 备用屏并改动 termios，之后再查询往往等不到终端应答，探测就会失败，于是只能沿用旧值，表现为「终端背景永远不变」。

### 终端背景判断反了怎么办

判断结果会显示在两个菜单的标题里（并标出是**自动**判断还是**手动**指定）。**直接改就行，不用记命令行参数**：

| 位置 | 操作 |
| --- | --- |
| 选择缓存 | 选 `⇄ 切换为深色/浅色终端` |
| 设置屏 | 移 `终端背景` 那一行回车，选 `自动探测` / `深色终端` / `浅色终端` |

**手动指定后，自动探测就再也覆盖不了它**（`cache/_prefs.json` 里记 `"manual": true`）。这一点很关键：有些 IDE 内置的模拟终端会对 OSC 11 回一个错误答案，如果不加这条锁，你手动改完下次照样被打回原形。

想交还自动探测，在设置屏里选 `自动探测`，或直接：

```bash
rm -f cache/_prefs.json        # 回到"重新探测、必要时再问一次"
```

如果终端既不设 `COLORFGBG` 也不回应 OSC 11 查询，程序探测不到，会在**菜单里**问一次：

```
  探测不到终端背景，请选一个（只问这一次，之后可随时改）
▸ 深色终端   黑底浅字，亮像素上墨
  浅色终端   白底深字，亮像素留白
```

之所以问而不是猜：终端背景是**环境**属性，猜错会一直被沿用。同理，它还保存在全局而不是每个视频的 `config.json` 里——按视频存的话，某一次存错就会自我强化，换终端也回不来。

想单次强制、不动偏好，用 `-i`（深色）或 `--no-invert`（浅色）。优先级是 **命令行 > 手动指定 > 自动探测 > 上次记住的**。

按键：

| 键 | 作用 |
| --- | --- |
| `↑` `↓`（或 `k` `j`） | 移动，首尾循环 |
| `Enter` | 确认；默认高亮在「开始转换」时即直接开始 |
| `Esc` / `q` | **退回上一层，不改动**（落点见下表）；没有上一层时退化成该屏的主动作 |
| `Home` / `End` | 跳到首项 / 末项 |
| `1`–`9` | 直接选中对应项 |

`Esc` 具体退到哪，逐屏写清楚了：

| 当前界面 | `Esc` / `q` 退到 |
| --- | --- |
| 选择作品（第一屏） | 无动作（已经是第一屏） |
| 选择视频 | 回到「选择作品」 |
| 选择音频 | 回到它真正的上一屏：有选过视频就回选视频、只选过作品就回选作品；一层菜单都没弹过时 = 「不使用音频（静音播放）」 |
| 选择缓存 | 「重新设置」→ 进设置屏（是进入下一屏，不是返回） |
| 设置屏（从缓存菜单进来的） | 回到「选择缓存」 |
| 设置屏（首次运行 / `--setup`，没有上一屏） | **直接开始转换** |
| 设置屏里的字符集 / Braille 抖动 / 插值 / 终端背景 | 回设置屏，该项保持不动 |
| 播放中 | 退出播放 |

**编号回退模式**（非 TTY）下没有 `Esc`，`cancel` 会显示成多出来的一行 `[0]`，设置屏则直接回车开始。

**设置屏**把所有参数摆在一屏，默认高亮「开始转换」，所以**一路回车就能开跑**；想改哪项就移上去回车：

```
  设置  ·  深色终端

    分辨率         180 x 51        ← 16:9 片源按比例算出来的
    字符集         braille  floyd|g1.5
    终端背景       深色终端（手动）
    帧率           视频自带
    抽帧步长       1
    插值方式       nearest
    OpenCV 线程    自动
  ▸ 开始转换
    ← 返回选缓存（不改动）      ← 只有从缓存菜单进来时才有这一行

  ↑↓ 选择   Enter 修改/开始   Esc 返回选缓存
```

最后那行「返回选缓存」只在有上一屏时出现（从缓存菜单选「重新设置」进来）；首次运行没有缓存、或用了 `--setup` 时，这一行不存在，底部提示也变成 `Esc 直接开始`。

**分辨率默认是按原片比例算的**，不用自己换算：终端字符格约为 1:2（高是宽的两倍），所以 `行数 = 列数 × 原片高 ÷ 原片宽 ÷ 2`；终端装不下时（比如竖屏视频）再整体等比缩小，避免播放时被裁掉一截。4:3 的片源用 90 列就是 90×34，16:9 是 90×25——直接套 90×30 会拉成"宽版普京"。

这套换算只在**高度没有明确指定**时生效：`-H`、或你上次手填过的尺寸（`config.json` 里 `height_auto: false`）都原样保留，不会被自动换算冲掉。字体格不是 1:2 的终端（比例古怪的等宽字体）仍会拉伸，这时把宽高一起手填即可。

选「字符集」会进二级菜单；选 braille 会接着问抖动方式和 gamma，**gamma 的默认值就是当前值**，所以反复进来改不会丢掉上次的设置。字符集菜单里 `Esc`/`q` = **保持当前不动**（编号模式下是 `[0] 保持当前（不改动）`）；Braille 抖动菜单里 `Esc` 则让整套 braille 参数保持不动，连 gamma 也不再追问。

设置屏里每一项的初值都按同一套优先级取：**命令行 > 上次用的（`config.json`）> 默认值**。所以在缓存菜单里选「重新设置」进来时，字符集、帧率、抽帧步长、插值、线程显示的都是上次实际用过的值，不用重设一遍。

**非 TTY 环境**（管道、重定向、CI、测试）会自动回退成编号输入，功能完全一致：

```
选择缓存  ·  深色终端（探测不到，可切换）
  [1] 180x60  braille [floyd|g1.5]   25 fps   ← 上次使用
  [2] 180x60  classic                25 fps
  [3] ⇄ 切换为浅色终端
  [0] 重新设置
序号 (0-3，回车默认 1):
```

## 目录结构

播放器代码放在仓库的 `Bad-Apple/` 子目录里，README 与 LICENSE 在仓库根目录：

```
GoodBadApple/
├── README.md
├── LICENSE
├── .gitignore
└── Bad-Apple/
    ├── Bad Apple.py   播放器主体：CLI、终端探测、缓存管理、curses 播放、菜单与设置屏
    ├── convert.py     转换引擎：视频 → ASCII 帧数据，可独立当库用
    ├── UI.md          界面状态图与常见流程（改界面代码前先看这份）
    ├── requirements.txt
    ├── data/          源素材，每个子文件夹算一个"作品"
    └── cache/         转换结果缓存，每个作品一个子目录
        ├── _prefs.json              全局偏好（终端背景），与具体视频无关
        └── rickroll__Rickroll/
            ├── 180x60_dark_block.pkl
            ├── 180x60_light_simple.pkl
            └── config.json          该视频上次使用的配置
```

`cache/` 和 `data/` 里的实际素材不进版本库（见 `.gitignore`），上面只是运行后的本地形态。

缓存文件名格式为 `{宽}x{高}_{dark|light}[_{字符集}].pkl`：`dark` / `light` 指的是**终端背景**（深色终端需要反转映射，让亮像素上墨）。未标注字符集即为默认的 `classic`；自定义字符集记为 `_custom<md5前6位>`；Braille 记为 `_braille<md5前6位>`（哈希的是抖动参数，例如 `90x30_dark_braille096074.pkl` 对应 `bayer|g1`）。

**抽帧步长和插值方式不进文件名**（否则加这两个维度会让现有缓存全部作废），它们记在缓存 payload 里。设置屏里改了这两项时，程序会核对 payload：一致就复用，不一致就打印原因并重新转换，覆盖同名文件。

> 因此同一个 `{宽}x{高}_{明暗}_{字符集}` 只能存一个变体，后转换的覆盖先前的。改了抽帧/插值后第一次播放会慢一点，这是正常的——换来的是"设置真的生效"，而不是被一个同名旧缓存静默顶掉。

**明暗极性可以互换，而且是无损的**：渲染器里 `invert` 恰好是最后一步整体取反（ASCII 是字符表镜像 `n-1-idx`，Braille 是 8 个点逐位取反），所以"把深色缓存取反"和"用浅色重新渲染一遍"得到的结果**逐字符完全相同**。于是同 key 缓存缺失时，程序会去翻反明暗的那一份：

```
同 key 缓存命中？ ── 否 ──> 反明暗同 key 缓存存在？ ── 是 ──> 取反（秒级）并落盘
        │                              └── 否 ──> 从视频转换
        └── 是 ──> 直接播放
```

本机实测（Apple M2，Braille）：

| 缓存 | 大小 / 帧数 | 加载 | 取反 | 落盘 | 合计 | 同样内容重新渲染 |
| --- | --- | --- | --- | --- | --- | --- |
| `90x30_dark_braille8eb980` | 52 MB / 6573 帧 | 0.38 s | 0.47 s | 0.07 s | **0.9 s** | ~39 s（floyd）+ 解码 |
| `180x60_dark_brailled84f32` | 166 MB / 5306 帧 | 0.19 s | 1.47 s | 0.21 s | **1.9 s** | ~31 s（floyd）+ 解码 |

取反结果会写到**当前**明暗的 key 下，所以只有第一次要多花这一两秒，之后就直接命中。缓存菜单里还有一键「⇄ 用深色缓存取反生成浅色版」（当前明暗一条缓存都没有时出现），不用进设置屏；设置屏里直接回车同样会走这条路。

两种情况不吃这个捷径，照旧从视频转换：`--rebuild`（你就是想重渲染），以及 `--chars` 自定义字符表里**有重复字符**（字符 ↔ 档位的映射不唯一，取反只能靠猜）。

命名规则对 Braille 同样成立，所以一个视频可以同时存在多个不同参数的 Braille 缓存，菜单里会带着参数一起显示：

```
发现该视频的 4 个可用缓存:
  [1] 90x30 | simple 30fps
  [2] 90x30 | braille [none|g1.2] 30fps
  [3] 90x30 | braille [floyd|g1.5] 30fps
  [4] 90x30 | braille [bayer|g1] 30fps  ← 上次使用
  [0] 重新设置
```

## 命令行选项

### 简单选项

| 选项 | 说明 |
| --- | --- |
| `-v, --video PATH` | 视频路径，不填则自动扫描 `data/` |
| `-b, --bgm PATH` | 背景音乐路径，不填则自动扫描同目录 |
| `-W, --width N` | 字符画宽度（默认 90，超过终端列宽时自动收窄） |
| `-H, --height N` | 字符画高度；**不填则按原片比例算**（`列数 × 原片高 ÷ 原片宽 ÷ 2`），装了终端装不下时再等比缩小 |
| `-c, --charset NAME` | 预设字符集（默认 `classic`） |
| `--chars STR` | 自定义字符表，从密到疏，覆盖 `--charset` |
| `--braille` | Braille 点阵模式，等价于 `-c braille` |
| `-L, --list-charsets` | 列出预设字符集并退出 |

### 高级选项

| 选项 | 说明 |
| --- | --- |
| `-f, --fps F` | 播放帧率，不填则用视频自带 |
| `-d, --delay S` | 音乐开始后延迟多少秒才出画面（默认 0.4） |
| `-i, --invert` | 强制反转（深色终端，亮像素用密字符） |
| `--no-invert` | 强制不反转（浅色终端） |
| `-r, --rebuild` | 忽略缓存，强制重新转换 |
| `--frame-step N` | 抽帧步长，`2` 表示隔一帧取一帧，转换时间减半；不填则沿用该视频上次的设置（默认 `1`） |
| `--interp MODE` | 缩放插值：`nearest`（默认）/ `area` / `linear` / `cubic`；不填则沿用该视频上次的设置 |
| `--braille-dither MODE` | Braille 抖动：`bayer`（默认）/ `floyd` / `none` |
| `--braille-gamma G` | Braille gamma 校正（默认 `1.0`，>1 提亮暗部） |
| `--threads N` | OpenCV 线程数，弱 CPU 上设 `1` 可减少调度开销 |
| `--setup` | 强制进入设置屏，跳过缓存菜单 |

### 预设字符集

| 名称 | 档数 | 说明 |
| --- | --- | --- |
| `classic` | 70 | 默认，细节最丰富 |
| `simple` | 10 | 通用 ASCII 梯度 |
| `block` | 5 | 方块字符，观感接近"像素画" |
| `minimal` | 4 | 极简 |
| `braille` | 点阵 | 2×4 点/字符，需要抖动配合，见下节 |

各字符集的实际字符表（从密到疏）：

```text
classic   $@B%8&WM#*oahkbdpqwmZO0QLCJUYXzcvunxrjft/\|()1{}[]?-_+~<>i!lI;:,"^`'. 
simple    @%#*+=-:. 
block     █▓▒░ 
minimal   @#. 
```

`block` 用方块字符，视觉上最不容易糊；`classic` 细节最多，但在小字号终端下容易变成一团噪点。用 `-L` 可以随时打印这份列表。

## Braille 点阵模式

前四个字符集是在**灰阶方向**下功夫（一个格子用不同密度的字符表示不同亮度），Braille 则是在**空间方向**下功夫：一个字符格子编码 2×4 个二值点，90×30 的窗口因此能出 **180×120 = 21600 个点**，是 ASCII 的 8 倍。代价是每个点只有 1 bit，灰阶得靠抖动（dithering）用点的疏密"骗"回来——这正是报纸和电子墨水屏的思路。

### 用法

```bash
# 最省事：默认 bayer 抖动
python3 "Bad Apple.py" --braille

# 指定抖动方式和 gamma
python3 "Bad Apple.py" --braille --braille-dither floyd --braille-gamma 1.5

# 等价写法
python3 "Bad Apple.py" -c braille --braille-dither floyd
```

首次转换时在字符集菜单里选 `braille` 也行，会接着追问抖动方式和 gamma。

### 三种抖动方式

Bayer 阈值矩阵，逐点比较，纯向量化：

```text
 0  8  2 10        灰度 0.3 的平坦区域
12  4 14  6   →   会变成规则的黑白交错点，
 3 11  1  9        人眼在一米外自动感知成灰
15  7 13  5
```

| 方式 | 效果 | 速度 | 适用 |
| --- | --- | --- | --- |
| `bayer` | 有序抖动，过渡均匀，静态画面偶有规则纹理 | 快 | 默认，长视频 |
| `floyd` | 误差扩散，层次最自然，无规则纹理 | 慢约 9 倍 | 短片、展示 |
| `none` | 直接硬阈值二值化 | 最快 | 高对比度片源（如 Bad Apple 原片） |

本机实测（Apple M2，90×30 → 180×120 点阵）：

| 方式 | 每帧耗时 | 3 分钟 30fps 视频 |
| --- | --- | --- |
| `bayer` | ~0.6 ms | ~20 秒 |
| `floyd` | ~5.9 ms | ~30 秒 |
| `none` | ~0.6 ms | ~20 秒 |

转换是一次性的，播放只读缓存，所以慢一点不影响观感。

### gamma 校正

视频像素是 sRGB 空间的，而人眼对亮度是非线性感知的。直接用原始亮度抖动会让暗部过暗。`--braille-gamma` 在抖动前做一次幂校正：`1.0` 为中性，`1.2~1.5` 提亮暗部（画面偏暗的片源），`0.8` 压暗。

### 注意事项

- **字体支持**：需要终端字体覆盖 Unicode 盲文块 `U+2800–U+28FF`。Windows Terminal、iTerm2、GNOME Terminal、Konsole 都默认支持；若显示成方块或问号，换个字体或退回 `classic`。
- **宽高比**：Braille 假设字符格是 1:2 的（高是宽的两倍），这样每个点才是正方形——ASCII 模式同理，所以默认分辨率本来就是按这个比例和原片比例一起算的。字体比例不是 1:2 的终端仍会拉伸，这是终端渲染的固有限制，把宽高一起手填即可。
- **点阵与参数一起进缓存**：`bayer|g1` 和 `floyd|g1.5` 是两个不同的缓存文件，互不覆盖。

## 工作原理

1. **取视频**：`cv2.VideoCapture` 逐帧读取，支持抽帧（`--frame-step`）。
2. **转字符**：转灰度 → `cv2.resize` 到目标宽高 → `idx = gray * n // 256` → 查字符表。整帧一次性向量化完成，再按需反转。
3. **存缓存**：pickle 序列化 `{settings, video_fps, video_data}`，`video_data` 是"每帧一个字符串列表"的结构。
4. **播放**：`curses` 清屏 + 逐行 `addstr`，`FpsTimer` 控制节奏；音频由 `pygame.mixer` 在进入 curses 之前加载并播放。

Braille 模式在第 2 步换用另一套渲染器：把画面缩到 `宽×2` × `高×4` 的点阵 → 抖动成 0/1 → 按位打包成 Braille 字符。其余流程完全一致，所以缓存、菜单、设置屏都不用改。

调整选项的优先级统一为：**命令行 > 已有缓存配置 > 交互询问 > 默认值**。字符集内部 `--chars` 优先于 `--braille` / `--charset`。

缓存命中复用还要求抽帧步长与插值方式和缓存里记的一致（这两项不在文件名里，见上文）；`config.json` 里另存一个 `fps_override` 记录"用户当时选的帧率"，因为 `fps` 字段存的可能是被抽帧除过的实际帧率。

取缓存的顺序是：**同 key 缓存 → 反明暗的同 key 缓存取反（无损，秒级）→ 从视频转换**。

播放中改变窗口大小会立即按新尺寸重排画面（`KEY_RESIZE`）；`q` / `Esc` 随时退出。

## 缓存说明

`cache/` 目前约 1.2 GB，因为帧数据以明文字符串 pickle 存放，体积基本与"视频时长 × 分辨率"成正比。

**可以随时整个删掉**，下次运行会重新转换，只是会慢一些。想只清某一种设置的缓存，按文件名删即可，例如删掉所有 90×30 的低清缓存：

```bash
rm -rf cache/*/*90x30*.pkl
```

注意 `cache/_prefs.json` 是全局偏好（终端背景），**不在通配范围内**；删掉它只会让程序重新探测并可能再问一次明暗，不影响缓存。想强制重新探测就删它：

```bash
rm -f cache/_prefs.json
```

## 与原项目的关系

### 原项目

- 只支持固定的 `data/1.flv` 和 `data/bgm.mp3`；
- 缓存文件 `video_data.py` 只有一份，换视频要手动删除；
- 没有终端背景检测，白底终端显示反色；
- 播放计时用 `count * FRAME_RATE`，长时间播放会累积误差；
- 逐像素 Python 循环转换，分辨率一高就非常慢。

### 本改进版新增

**工程结构**

1. **`data/` 自动扫描**：按扩展名识别视频和音频，多候选时列出菜单。
2. **一作品一文件夹**：缓存按「相对 `data/` 的路径」区分，同名不同目录互不干扰。
3. **音频可选**：无音频静音播放；同目录同名自动配对；加载失败有提示并降级。
4. **统一交互层**：作品 / 视频 / 音频 / 缓存 / 字符集 / 设置全部走同一套方向键菜单，非 TTY 自动回退编号输入，每层都能 `Esc` 原路退回。

**缓存与管理**

5. **智能缓存管理**：每个视频独立子目录，分辨率 / 明暗 / 字符集互不覆盖。
6. **抽帧与插值进 payload**：改了这两项会核对缓存，不一致就重转，不被同名旧缓存静默顶掉。
7. **明暗取反复用**：缺当前明暗的缓存时，把反明暗的那份逐字符取反来用，无损且秒级，不重新解码视频。
8. **缓存复用**：设置屏结束先按新设置查一遍缓存，命中直接播放。
9. **pickle 缓存**：替代 `.py` 缓存，加载更快、文件更小。

**Braille 点阵（本版新增）**

10. **Braille 渲染器**：一个字符编码 2×4 个点，同样窗口下点数是 ASCII 的 8 倍。
11. **三种抖动 + gamma 校正**：`bayer` / `floyd` / `none`，参数一起进缓存名，互不覆盖。

**终端适配**

12. **终端背景自动适配**：OSC 11 查询 + `COLORFGBG` 兜底，自动决定是否反转；手动指定后自动探测不再覆盖。
13. **终端恢复保护**：信号处理 + `atexit` + 播放前 `bkgd()` 钉住擦除填充色，异常退出也不会留在 raw 模式，并消除部分终端的白条残留。
14. **跨平台**：Windows 用 `msvcrt.getch()`，Linux / macOS 用 `tty.setraw`；播放中改变窗口大小会按新尺寸重排。

**性能**

15. **向量化转换**：`numpy` + OpenCV 整帧映射，替代逐像素 Python 循环。
16. **抽帧加速**：`--frame-step 2` 隔一帧取一帧，转换时间减半。
17. **OpenCV 线程控制**：`--threads 1` 在弱 CPU 上减少调度开销。
18. **`FpsTimer` 精确计时**：基于 `perf_counter()` 的补偿式计时，长时间播放不漂移。
19. **比例自适应默认分辨率**和**进度条**：不用自己换算尺寸，转换时能看到百分比与已处理帧数。

## 常见问题

**音频加载失败 / 静音播放**
pygame 只保证支持 `wav` / `ogg` / `mp3`，`m4a` / `flac` / `aac` / `wma` 取决于 SDL_mixer 的编译情况。程序检测到加载失败会提示并降级为静音播放。建议先把音频转成 mp3：

```bash
ffmpeg -i input.m4a -vn -c:a libmp3lame output.mp3
```

**视频打不开**
OpenCV 的可解码范围取决于其后端（ffmpeg / gstreamer）。常见可用的有 `mp4` / `avi` / `mkv` / `flv` / `mov` / `webm`；遇到冷门编码先用 ffmpeg 转成 mp4。

**画面明暗反了 / 整个屏幕发黑**
程序启动时会用 OSC 11 探测终端背景（`COLORFGBG` 兜底），深色终端自动开启反转、浅色终端关闭。**判断反了就会整幅变负片**：亮的地方不上墨，露出终端自己的底色，于是看起来"屏幕变成黑底"、人物肤色和头发都反了。

这不是 curses 画了黑底——字符画只画字符，不画背景；你看到的"黑"就是终端自己的背景色透出来。改判断即可：

| 位置 | 操作 |
| --- | --- |
| 选择缓存 | 选 `⇄ 切换为深色/浅色终端` |
| 设置屏 | 移 `终端背景` 那一行回车 |

切换结果存进 `cache/_prefs.json`，下次自动沿用。也可以用 `-i`（深色）/ `--no-invert`（浅色）临时强制：

```bash
python3 "Bad Apple.py" -i            # 强制反转（深色终端）
python3 "Bad Apple.py" --no-invert   # 强制不反转（浅色终端）
```

程序会按终端背景过滤可用缓存，深浅两套缓存分别存放、互不干扰。Braille 模式同样受这个开关控制。

**被问了「探测不到终端背景」**
该终端既不设 `COLORFGBG`，也不回应 OSC 11 查询。选一次即可，会记进 `cache/_prefs.json`，之后不再问。想更省事可以设 `COLORFGBG`（格式 `前景;背景`，背景 ≥ 7 视为浅色）。删掉 `cache/_prefs.json` 可以让它重新探测并再问一次。

**播放时出现横贯画面的白条**
某些终端（尤其 **IDE 内置的模拟终端**，如 PyCharm 的 Run/Debug 控制台）是 bce（背景色擦除）的：curses 画连续空格时会改用 `ECH`/`EL`，"填充色"取的是**当前背景色**。如果没有把窗口背景显式钉成终端默认色，整片空格就会被填成别的颜色——于是只在"空格段"上出现白条，同一行的字符却完全正常。

程序启动播放前会调用 `_init_colors()`：`start_color()` + `use_default_colors()` + `init_pair(1, -1, -1)`，再用 `bkgd()` 把擦除填充色设成终端默认前景/背景。如果你的终端仍出现白条：

1. 先换个**真实终端**（Terminal.app / iTerm2 / Windows Terminal）跑，确认是否是 IDE 模拟终端的渲染问题；
2. 减小画面尺寸（`-W 120 -H 40`）或抽帧（`--frame-step 2`），降低终端的重绘压力。

**Braille 模式显示成方块或问号**
终端字体不支持 Unicode 盲文块 `U+2800–U+28FF`。换一款等宽字体（或用 Windows Terminal / iTerm2 / GNOME Terminal / Konsole 的默认字体），或退回 `classic` 等字符集。

**Braille 的 floyd 抖动转换很慢**
误差扩散是串行算法，没法向量化。长视频用默认的 `bayer`，或对高对比度片源用 `none`：

```bash
python3 "Bad Apple.py" --braille --braille-dither none
```

**画面和音乐不同步**
先用 `--frame-step` 确认不是转换太慢导致的；若视频本身帧率异常（可变帧率），用 `-f 30` 之类手动指定。

**菜单变成编号列表了**
说明当前不是 TTY（比如 `python3 "Bad Apple.py" | tee log`，或从 IDE 里跑）。这是有意的回退，功能完全一样，只是改用数字选择。想看方向键菜单请直接在终端里运行。

**画面被拉宽/拉扁了（"宽版普京"）**
默认分辨率是按原片比例算的（见「界面操作」），所以新转换的都不会变形。如果**已经**有一份不对比例的缓存（比如老版本的 90×30），它在缓存菜单里仍然能选、能放，只是比例不对；想要正确比例就选「重新设置」→ 直接回车，会用新比例转一份出来。字体格不是 1:2 的终端仍会拉伸，把宽高一起手填（`-W 120 -H 40`）即可。

**只有另一种明暗的缓存，会重新转换一遍吗？**
不会。同 key 缓存缺失时会先找**反明暗**的那一份，逐字符取反来用（与重新渲染完全一致，一两秒），并把结果存到当前明暗的 key 下。只有 `--rebuild`、或 `--chars` 自定义字符表里有重复字符时才会真的重新转换。详见「缓存说明」。

**菜单错位 / 花屏**
检查 `TERM` 环境变量（`echo $TERM` 应类似 `xterm-256color`）。`TERM=dumb` 或未设置时会自动退回编号菜单；`TERM` 与终端实际类型不匹配则可能出现乱码。

**播放时终端花屏**
正常退出（`q` / `Esc` / Ctrl+C）都会自动恢复。若被 `kill -9` 强杀，在终端执行 `reset` 或 `stty sane` 即可。
